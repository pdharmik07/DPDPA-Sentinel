# Deployment

## Environment variables

### `backend/.env`

| Key | Required | Notes |
|---|---|---|
| `DATABASE_URL` | yes | PostgreSQL connection string |
| `JWT_SECRET` | yes | **≥ 32 chars.** Generated for you by `npm run setup` locally and by `render.yaml` in production. Server refuses to start without it |
| `JWT_EXPIRES_IN` | no | default `12h` |
| `BACKEND_PORT` | no | default `4000`. A platform-injected `PORT` takes precedence |
| `NODE_ENV` | no | `development` \| `test` \| `production` |
| `FRONTEND_URL` | yes in prod | comma-separated CORS allowlist |
| `NLP_SERVICE_URL` | no | default `http://localhost:8000` |
| `NLP_ENABLED` | no | `false` disables the NLP call entirely |
| `NLP_TIMEOUT_MS` | no | default `15000` |
| `UPLOAD_MAX_SIZE` | no | bytes, default `10485760` |
| `UPLOAD_TMP_DIR`, `REPORT_DIR` | no | defaults `./uploads`, `./reports` |
| `LOG_LEVEL` | no | default `info` |
| `ANALYSIS_CONCURRENCY` | no | default `2` |

The environment is validated by Zod at boot; a missing or weak value fails fast with a message
naming the key (never the value).

### `frontend/.env.local`

| Key | Notes |
|---|---|
| `VITE_API_URL` | Base URL of the backend, e.g. `https://api.example.com` |

Only `VITE_*` variables are exposed to the browser. Never put a secret in one.

### `nlp-service/.env`

| Key | Notes |
|---|---|
| `ALLOWED_ORIGINS` | should be the backend origin only |
| `NLP_WARM_START` | `true` preloads models at startup |

## Local database without Docker

Docker Desktop on Windows Home requires WSL2, which is not always available. The backend therefore
ships an embedded PostgreSQL harness that needs no Docker and no admin rights:

Migrate and seed a persistent local database:

```bash
cd backend
```

```bash
npm run db:local:setup
```

Then start PostgreSQL and the API together:

```bash
npm run db:local
```

Run a single command against a throwaway database:

```bash
npx tsx scripts/withDb.ts "<any command>"
```

The harness forces `--encoding=UTF8 --locale=C`. Without it, `initdb` inherits the Windows locale
and builds a WIN1252 cluster that cannot store the em-dashes and arrows in the rule pack. The
`postgres:16-alpine` image in `docker-compose.yml` is UTF8, so this keeps local and production
faithful to each other.

**Any production database must be UTF8.**

## Making the public URL work (Vercel + Render)

The Vercel deployment serves **only the frontend**. Every screen is an API call, so until a backend
is hosted somewhere public the deployed site cannot work for anyone — its default `VITE_API_URL`
points at `http://localhost:4000`, which on a visitor's machine means *their own* computer. Browsers
also refuse to let an HTTPS page call `http://localhost` at all (`ERR_BLOCKED_BY_CLIENT`), so there
is no configuration that makes the hosted site talk to a laptop.

Two pieces have to exist: the API and its database. `render.yaml` at the repository root creates
both.

### 1. Deploy the backend and database

1. Push this repository to GitHub.
2. Sign in at <https://render.com> and choose **New → Blueprint**.
3. Select this repository. Render reads `render.yaml` and proposes a web service
   (`dpdpa-sentinel-api`) plus a PostgreSQL database (`dpdpa-sentinel-db`).
4. It asks for the one value that cannot be guessed — `FRONTEND_URL`. Enter your frontend origin,
   with no trailing slash:

   ```
   https://dpdpa-sentinel.vercel.app
   ```

5. **Apply**. The first build takes a few minutes. `JWT_SECRET` is generated by Render and
   `DATABASE_URL` is wired to the database automatically; neither is ever committed.

On every deploy the start command runs `prisma migrate deploy`, seeds the 41-rule pack, then starts
the API, so the schema and rules are always in place. Confirm it is live:

```
https://<your-service>.onrender.com/api/health
```

Expect `{"status":"ok","database":"up","rules":41}`.

### 2. Point the frontend at it

In the Vercel project → **Settings → Environment Variables**, add:

| Key | Value |
|---|---|
| `VITE_API_URL` | `https://<your-service>.onrender.com` |

Then **redeploy**. Vite inlines `VITE_API_URL` at build time, so setting it without rebuilding
changes nothing — this is the single most common reason the deployed site keeps failing after the
backend is up.

### 3. Check it from another machine

Open the Vercel URL in a different browser (or on a phone on mobile data) and register an account.
Nothing should reference `localhost`.

### What to expect on the free tier

- **Cold starts.** A free Render service sleeps after ~15 minutes idle; the next request takes
  roughly 50 seconds to wake it. The first page load after a quiet period looks slow, then is fast.
- **Free databases expire.** Render's free PostgreSQL is removed after 30 days. For anything that
  must keep working — a demo you are being marked on — use a paid instance or re-create it and
  re-run the seed.
- **Uploads and generated PDFs are ephemeral.** The filesystem is wiped on each deploy. This is
  fine: PDFs are generated per request from the database, not served from disk.
- **No NLP service.** `render.yaml` sets `NLP_ENABLED=false`. Scans run on the deterministic engine
  and are flagged `nlpAvailable: false`, which is a supported mode, not a degraded one.

### If the deployed site still shows an error

| What you see | Cause |
|---|---|
| *This site is hosted, but it is calling http://localhost:4000* | `VITE_API_URL` is not set on Vercel, or it was set without redeploying. |
| A CORS error in the browser console | The Vercel origin is not in `FRONTEND_URL` on Render. It must match exactly — scheme, host, no trailing slash. Vercel preview deployments get their own origins and need adding too. |
| First request hangs ~50s, then works | Free-tier cold start. Expected. |

## Checklist

- [ ] `JWT_SECRET` is freshly generated per environment and never committed
- [ ] `FRONTEND_URL` lists only real origins (no wildcard)
- [ ] `NODE_ENV=production` — suppresses the `debug` field on 500 responses
- [ ] TLS terminated in front of the backend; `trust proxy` is already set to 1
- [ ] `reports/` and `uploads/` are writable and not publicly served
- [ ] Database backups configured — `Scan.extractedText` holds user-uploaded policy text
- [ ] `npm test` green in CI before deploy
